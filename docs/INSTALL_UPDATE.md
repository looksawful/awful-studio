# AWFUL STUDIO 0.0.17 — Install, Update and Troubleshooting

AWFUL STUDIO 0.0.17 targets Blender 5.2 LTS. The exact release runtime is qualified against Blender 5.2.1 build `9e2066aef7ef` on Windows and Ubuntu.

The Extension manifest supports Blender `>= 5.2.0` and `< 5.3.0`.

## Before installation

- Use the exact release/candidate ZIP named `awful_studio-0.0.17.zip`.
- Do not unpack or rename the package before Blender installs it.
- A candidate ZIP is not a public release until the final manual UI smoke passes and the release is explicitly tagged/published.
- Base Studio operation is offline. Network access is needed only for Extension repository synchronization/update or an explicitly requested optional asset download.

## Install from Disk

Use this path for the final candidate smoke and for direct ZIP installation:

1. Open Blender 5.2.
2. Open **Edit → Preferences → Extensions**.
3. Open the Extensions menu and choose **Install from Disk**.
4. Select `awful_studio-0.0.17.zip`.
5. Enable **AWFUL STUDIO** if Blender does not enable it automatically.
6. Return to the 3D Viewport and open the sidebar with `N`.
7. Open the **AWFUL STUDIO** tab.

Installation or enabling must not build or mutate the current scene. **Build Studio** remains an explicit user action.

### Updating an Install from Disk candidate

When replacing a test candidate, disable/remove the installed AWFUL STUDIO Extension through Blender Preferences and install the new exact ZIP. Preserve user `.blend` files separately; an Extension package is not a backup mechanism.

## Extension Repository

The production update path is a Blender-native Extension Repository generated by Blender's Extension CLI.

When the production repository URL is published with the release:

1. Open **Edit → Preferences → Extensions**.
2. Add the published AWFUL STUDIO Extension Repository URL.
3. Allow online access for the repository sync operation when Blender requests it.
4. Sync/refresh the repository.
5. Search for **AWFUL STUDIO** and install version `0.0.17`.
6. Restart Blender when an update specifically requires it, then reopen the saved AWFUL scene.

Do not invent or hard-code a repository URL before publication. CI verifies the same native repository mechanism against an isolated generated repository before release.

## First use

After installation:

1. Open `N → AWFUL STUDIO`.
2. Choose **Build Studio**.
3. Use the preset-driven Product / Camera / Lighting / Environment workflow.
4. Use **Fast Preview** for responsive look development and **Quality Preview** when a cleaner Rendered Viewport is useful.
5. Use **Setup Post Pipeline** only when Light Groups, passes and the managed compositor are wanted.
6. Continue to use Blender's native controls for native material, camera, light, render and Cycles device properties.

The candidate includes Bottle, Jar, Box, Can, Phone and Tablet starters plus deterministic offline starter materials. AWFUL-owned mockup replacement must not delete unmanaged mounted user products.

## Rendered Viewport and GPU device

AWFUL intentionally does not rewrite Blender's CUDA/OPTIX/HIP/ONEAPI/METAL preferences or silently switch the Cycles scene Device.

That distinction matters: a Blender profile can have OPTIX configured globally while a new scene still has **Render Properties → Cycles → Device = CPU**. In that state Rendered Viewport can be dramatically slower even on a powerful GPU.

For workstation performance checks:

1. use the normal Blender profile rather than a factory-clean correctness profile;
2. open **Render Properties**;
3. confirm Cycles is the render engine;
4. set **Device → GPU Compute** when GPU rendering is the intended workstation configuration;
5. use the AWFUL diagnostics line to confirm the scene is not accidentally CPU-backed;
6. compare **Fast Preview** and **Quality Preview** while navigating the Rendered Viewport.

Fast/Quality Preview changes viewport-only controls. It does not change final render samples, final output resolution, Light Tree policy, or the selected Cycles device/backend.

## Network and optional HDRIs

- Base Build, Rebuild, preset switching and procedural mockup generation make no required network request.
- **Download All HDRIs** is an explicit network action for the reviewed HDRI set.
- Blender Online Access remains authoritative; AWFUL also requires its explicit network consent.
- Successful downloads become available without forcing a surprise environment switch.
- If a selected HDRI is unavailable, AWFUL keeps the user's selected intent while using Physical Sky as a usable fallback.
- Blender's standard magenta missing-texture diagnostic is not suppressed. If a supposedly successful AWFUL HDRI path shows magenta, treat that as a defect and record it.
- The optional-asset cache cleanup path is limited to AWFUL-owned provenance files.

Third-party asset provenance and licenses are documented in `docs/THIRD_PARTY_ASSETS.md`.

## Post Pipeline

**Setup Post Pipeline** prepares the optional professional post workflow:

- Cycles Light Groups;
- render passes;
- managed compositor stack.

It is intentionally not created during normal Build/Rebuild. After setup the UI reports **Post Pipeline: Ready**. Running setup again asks for confirmation in interactive Blender and rebuilds idempotently. The pipeline is qualified to remain usable after save/reopen.

## Troubleshooting

### AWFUL STUDIO is installed but no studio appears

Expected. Registration is scene-clean. Open `N → AWFUL STUDIO` and run **Build Studio** explicitly.

### Rendered Viewport is unexpectedly slow

Check the AWFUL device diagnostic and Blender **Render Properties → Device** first. If the scene says CPU while GPU Compute is intended, switch the scene through Blender's native control. AWFUL will not silently make that hardware decision for you.

### Repository sync or HDRI download is blocked

Blender must allow online access for explicit repository/HDRI network operations. AWFUL's core studio remains usable offline. The UI should explain a blocked online-access state rather than silently failing.

### Optional HDRI shows Blender magenta

Magenta is Blender's normal missing-texture diagnostic. Do not hide it. Confirm the download/status state; a successful AWFUL happy path is expected to have a valid loaded image and should not show magenta.

### Setup Post Pipeline reports unavailable capability

Use Blender 5.2 LTS, preferably the exact qualified Blender 5.2.1 build. The action probes the live Blender capability at invocation time so save/reopen does not rely on stale Python process state.

### Historical 0.0.15 scene is detected

Use **Upgrade Historical AWFUL Scene**. Migration is explicit; the historical source remains immutable compatibility evidence.

### Build/Rebuild appears to change GPU settings

That is not expected. Build/Rebuild preserves Blender's native Cycles device/backend selection. Record the exact Blender version and reproduction steps if this occurs.
