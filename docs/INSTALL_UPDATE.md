# AWFUL STUDIO 0.0.17 — Install, Update and Troubleshooting

AWFUL STUDIO 0.0.17 targets Blender 5.2 LTS. The exact release runtime is verified against Blender 5.2.1 build `9e2066aef7ef` on Windows and Ubuntu.

The Extension manifest supports Blender `>= 5.2.0` and `< 5.3.0`.

## Before installation

- Use the exact release ZIP named `awful_studio-0.0.17.zip`.
- Do not unpack or rename the package before Blender installs it.
- A candidate ZIP is not a public release until the final manual UI smoke passes and the release is explicitly tagged/published.
- Base studio operation is offline. Network access is needed only for Extension repository synchronization/update or an explicitly requested optional asset download.

## Install from Disk

Use this path for the final candidate smoke and for direct ZIP installation:

1. Open Blender 5.2.
2. Open **Edit → Preferences → Extensions**.
3. Open the Extensions menu and choose **Install from Disk**.
4. Select `awful_studio-0.0.17.zip`.
5. Enable **AWFUL STUDIO** if Blender does not enable it automatically.
6. Return to the 3D Viewport and open the sidebar with `N`.
7. Open the **AWFUL STUDIO** tab.

Installation or enabling must not build or mutate the current scene. **Build Studio** remains an explicit user action.

### Updating an Install from Disk installation

Install from Disk is appropriate for a specific candidate ZIP, but it is not the preferred long-term update channel. When testing a replacement candidate, disable/remove the installed AWFUL STUDIO Extension through Blender Preferences, then install the new exact ZIP. Preserve user `.blend` files separately; AWFUL scene ownership/migration behavior is tested at the Extension level, but a release package should never be treated as a backup mechanism.

## Extension Repository

The production update path is a Blender-native Extension Repository generated by Blender's own Extension CLI.

When the production repository URL is published with the release:

1. Open **Edit → Preferences → Extensions**.
2. Add the published AWFUL STUDIO Extension Repository URL in Blender's repository settings.
3. Allow online access for the repository sync operation when Blender requests it.
4. Sync/refresh the repository.
5. Search for **AWFUL STUDIO** and install version `0.0.17`.
6. Restart Blender when an update specifically requires it, then reopen the saved AWFUL scene.

Do not invent or hard-code a repository URL before the production repository is actually published. CI verifies the same native repository mechanism against an isolated generated repository before release.

### Updating from the Extension Repository

1. Sync/refresh the configured repository.
2. Use Blender's native Extension update action for AWFUL STUDIO when a newer version is available.
3. Reopen the saved scene after the update.
4. If the scene was created by the historical 0.0.15 script and Blender presents the migration path, use **Upgrade Historical AWFUL Scene** explicitly before destructive studio operations.

AWFUL does not silently migrate historical scenes on import/register/enable.

## First use

After installation:

1. Open `N → AWFUL STUDIO`.
2. Choose **Build Studio**.
3. Use AWFUL workflow controls for studio presets, product mockups and visibility.
4. Continue to use Blender's native controls for native material, camera, light and render properties.

The 0.0.17 candidate includes procedural Bottle, Jar, Box, Can, Phone and Tablet mockups plus deterministic offline starter materials. Selecting an AWFUL mockup may replace only AWFUL-owned mockup data; it must not delete or reparent an unmanaged mounted user product.

## Network and optional assets

- Base Build, Rebuild, preset switching and procedural mockup generation make no required network request.
- Optional HDRIs are downloaded only after explicit user intent and are checked against the reviewed asset provenance inventory.
- The optional-asset cache cleanup path is limited to AWFUL-owned provenance files.
- If Blender is in offline mode, the core studio remains usable; optional remote assets and repository sync/update naturally cannot download.

Third-party asset provenance and licenses are documented in `docs/THIRD_PARTY_ASSETS.md`.

## Troubleshooting

### AWFUL STUDIO is installed but no studio appears

This is expected immediately after installation. Registration is scene-clean. Open `N → AWFUL STUDIO` and run **Build Studio** explicitly.

### Repository sync is blocked by online-access policy

Blender 5.2 requires online access to be enabled for repository synchronization, even when testing a repository through a local/file-backed repository path. Enable Blender online access only for the explicit repository sync/update operation. Core AWFUL Build/Rebuild does not require it.

### Optional HDRI is unavailable

Confirm that Blender online access is allowed and request the optional asset explicitly. AWFUL must not silently replace a missing Pure HDRI selection with a different environment regime.

### Historical 0.0.15 scene is detected

Use **Upgrade Historical AWFUL Scene**. Migration is explicit. The immutable historical source remains preserved in the repository for compatibility evidence.

### Build/Rebuild appears to change GPU settings

That is not expected in 0.0.17. Build/Rebuild preserves Blender's native Cycles device selection and does not enumerate GPU backends. Report the exact Blender version and reproduction steps if this occurs.

### A generated mockup does not frame safely

Use the normal AWFUL Auto Fit/camera controls and record the product/mockup, camera settings and scene state. Product-bounds framing is covered structurally for the six built-in 0.0.17 mockups.

## Release evidence

Before 0.0.17 can be tagged or published, the exact candidate must have:

- fast/static tests green;
- exact built ZIP validation;
- Blender 5.2.1 packaged runtime green on Windows and Ubuntu;
- native Extension repository generation/sync/install green on Windows and Ubuntu;
- release-hygiene checks green;
- the final manual UI smoke completed against that candidate.

The smoke is the final human gate, not a replacement for CI and not a render benchmark.
