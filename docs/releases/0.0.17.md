# AWFUL STUDIO 0.0.17 Release Notes

Status: pre-release candidate. This version is **not tagged or published** until the final manual UI smoke passes against the exact candidate artifact.

## Highlights

AWFUL STUDIO 0.0.17 moves the project from the Extension Foundation into a production-usable Product Quality slice while preserving the scene-safety, offline and native-Blender authority rules established during 0.0.16 development.

### Studio and architecture

- Metric cyclorama placement with derived room bounds.
- White, Black and Chroma Green cyclorama looks.
- Matte, Medium and Glossy cyclorama finishes.
- Independent visibility for walls, visible floor, ceiling, door, window frame, window glass and cyclorama.
- Visible studio floor separated from hidden bounce geometry.
- Real managed door opening instead of a decorative plane.

### Lighting and environment

- Photographic Flash regime with off-axis camera flash placement.
- Direct, Wide, Neutral Ambient and Color Ambient Flash family.
- Pure HDRI semantics without hidden Nishita fallback.
- Physical Sky with a dedicated managed Sun.
- Zero-energy portal sampling helper for Physical Sky only.
- Artificial studio lights can be disabled independently from natural environment lighting.

### Camera

- Product-bounds framing uses all eight bounds corners.
- Framing accounts for lens, render aspect, camera shift, product depth and vertical tilt.
- No arbitrary legacy 10 m camera-distance clamp.
- Native manually edited lens remains authoritative until an explicit AWFUL reset/default action.

### Product Quality

0.0.17 adds deterministic procedural product starters:

- Bottle;
- Jar;
- Box;
- Can;
- Phone;
- Tablet.

Starter material policies cover matte/glossy plastic, anodized metal, clear/dark glass, ceramic, cardboard, paper label and screen/emissive use where applicable.

Generated mockups use plausible real-world dimensions, deterministic origins/bottom planes, measurable bounds, bounded geometry cost and predictable material slots. Selecting an AWFUL mockup may replace only AWFUL-owned mockup data; unmanaged mounted user products survive.

Auto Fit and safe camera framing are integrated for all six built-in mockups and remain stable across Rebuild.

### Motion

Product and Camera playback policies are independent and support:

- Once;
- Loop;
- Ping-Pong.

Repeated policy application does not accumulate Cycles modifiers/actions.

### Extension/runtime safety

- Import/register/enable/restart remain scene-clean.
- Build/Rebuild/Remove remain explicit and scene-owner scoped.
- Role strings and object names alone never grant destructive ownership.
- Historical 0.0.15 migration remains explicit and preserves the immutable historical source.
- Base studio operation is offline.
- Optional asset downloads require explicit user intent and reviewed provenance.
- Build/Rebuild no longer probes or selects GPU backends automatically.
- Ordinary structural runtime contains no render invocation.

## Verified compatibility target

- Blender 5.2 LTS.
- Exact release runtime: Blender 5.2.1 build `9e2066aef7ef`.
- Manifest compatibility: Blender `>= 5.2.0` and `< 5.3.0`.

The final candidate must pass the exact built ZIP runtime and native Extension Repository install path on GitHub-hosted Windows and Ubuntu runners after release-prep changes are integrated.

## Installation and update

See `docs/INSTALL_UPDATE.md`.

The release supports two installation paths:

- Blender **Install from Disk** using the exact `awful_studio-0.0.17.zip` candidate/release artifact;
- Blender-native **Extension Repository** install/update after the production repository URL is published.

The production repository URL is intentionally not invented or hard-coded before publication.

## Known non-blocking items

These are not 0.0.17 release blockers:

- deterministic rendered visual-regression harness (#4);
- Flue live-runtime bridge evaluation (#1);
- Blender Agent Studio evaluation (#2);
- expanded motion library;
- volumetrics;
- larger HDRI library;
- additional physical fixtures/modifiers.

The absence of #4 means this release does not claim automated rendered visual approval. Structural/runtime QA and the manual UI smoke are separate evidence layers.

## Final manual UI smoke

This is the last human acceptance gate before release. It does **not** require rendering and should be run against the exact candidate artifact produced by the final cloud gate.

- [ ] Install `awful_studio-0.0.17.zip` through Blender 5.2.1 **Install from Disk**.
- [ ] Confirm install/enable does not build or mutate the open scene.
- [ ] Open `N → AWFUL STUDIO`.
- [ ] Run **Build Studio**.
- [ ] Switch representative Commercial/Flash/Natural lighting and environment controls.
- [ ] Confirm cyclorama distance/look/finish controls respond in the viewport.
- [ ] Toggle Walls / Floor / Ceiling / Door / Window Frame / Window Glass / Cyclorama independently.
- [ ] Generate Bottle / Jar / Box / Can / Phone / Tablet and inspect that each appears plausibly placed and bounded.
- [ ] Confirm Auto Fit behaves sensibly for the six built-in mockups.
- [ ] Check Product playback Once / Loop / Ping-Pong.
- [ ] Check Camera playback Once / Loop / Ping-Pong independently.
- [ ] Run Rebuild and confirm the selected AWFUL mockup/Auto Fit state remains usable.
- [ ] Save the `.blend`, close Blender, reopen it and confirm the studio remains usable.
- [ ] Run Remove Studio and confirm unmanaged user data remains.

If any smoke item fails, do not tag or publish 0.0.17. Record the exact candidate SHA/artifact, Blender version and reproduction steps in a new/focused issue rather than silently changing the release candidate.
