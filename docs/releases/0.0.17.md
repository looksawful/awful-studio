# AWFUL STUDIO 0.0.17 Release Notes

Status: corrective pre-release candidate. This version is **not tagged or published** until the final manual UI smoke passes against the exact integrated candidate artifact.

## What 0.0.17 is

0.0.17 is the first production-usable MVP slice after the Extension Foundation. It combines the Product Quality work with fixes found during the first real manual smoke rather than publishing the earlier defective candidate.

The old pre-smoke ZIP with SHA-256 `cc3a404ecc00e82e82716c91aece6260affd3c30d92bff1330b540965e489540` is retained only as defect-reproduction evidence and must not be released.

## Product and Auto Fit

- Procedural Bottle, Jar, Box, Can, Phone and Tablet starters.
- Offline starter materials for plastic, metal, glass, ceramic, cardboard, labels and screens.
- Product mounting now derives placement from actual world-space bounds instead of trusting arbitrary imported origins.
- Products are centered in X/Y and grounded deterministically on the intended support plane when the active motion policy expects contact.
- Auto Fit remains a coordinated high-level workflow while product placement, support fit and camera framing stay independently testable.
- Rebuild preserves owner-safe product behavior; unmanaged mounted user data survives.

## Motion and Timeline

Product and Camera animation remain independent and support Once, Loop and Ping-Pong.

The Blender Preview Range now follows generated motion without changing the global render frame range:

- Once: one keyed span;
- Loop: two complete spans;
- Ping-Pong: one forward + backward cycle;
- Product + Camera: union of the active preview spans.

The current frame is preserved when it remains valid and clamped only when it falls outside the new preview range. AWFUL also exposes explicit Fit Timeline to Motion and Reset Timeline actions.

## Lighting and environment

- Hybrid Studio + World is the normal product-lighting regime.
- Flash/cinematic preset families may intentionally use Studio-only behavior.
- World illumination and camera-visible background brightness are independent.
- Camera BG uses Blender ray-path semantics and does not secretly change environment energy illuminating the product.
- Cyan/magenta lighting remains a stylized preset family rather than the universal default look.
- Physical Sky retains its managed Sun/portal semantics.

## HDRI workflow

- Reviewed HDRIs can be fetched through the explicit bulk download workflow.
- Blender Online Access and AWFUL network consent remain distinct permissions.
- Missing/unavailable HDRI data falls back to a usable Physical Sky path without changing the user's selected HDRI intent.
- Blender's magenta missing-texture diagnostic is not hidden. Instead, runtime tests require AWFUL happy paths to load/assign valid image data rather than silently producing a missing texture.
- Errors/status are surfaced explicitly; base Build/Rebuild remains offline.

## Post Pipeline

`Setup Post Pipeline` remains optional during normal studio work but is now a qualified professional workflow:

- Blender 5.2 live capability detection;
- Cycles Light Groups;
- required render passes;
- managed compositor stack;
- Ready/rebuild state;
- idempotent repeated setup;
- save/reopen support with the existing studio ownership identity rebound safely in the new Blender process;
- explicit unsupported-capability cancellation rather than a silent no-op.

Normal Build/Rebuild does not create the Post Pipeline automatically.

## Rendered Viewport performance

The first manual smoke exposed severe Rendered Viewport/camera-navigation lag. Minimal target-machine diagnostics found that the deliberately isolated smoke profile had removed the normal Cycles GPU preferences and was running the scene on CPU, so the RTX GPU was not involved at all.

0.0.17 therefore:

- keeps Blender/user authority over Cycles device/backend selection;
- never silently rewrites CUDA/OPTIX/HIP/ONEAPI/METAL preferences;
- exposes explicit Fast Preview and Quality Preview modes;
- changes viewport-only samples/pixel size/adaptive threshold/denoise, never final render samples/resolution/device;
- shows compact diagnostics including active scene device/backend and warns clearly when Cycles is CPU-backed.

For the final performance smoke, Blender's scene Device must be deliberately set to **GPU Compute** when that is the intended workstation configuration. A factory-isolated CPU profile is valid for correctness testing but not for judging interactive GPU performance.

## Final manual UI smoke

This is the last human acceptance gate before release. It does **not** require a final image render and must be run against the exact integrated candidate artifact.

- [ ] Install the exact `awful_studio-0.0.17.zip` through Blender 5.2.1 **Install from Disk**.
- [ ] Confirm install/enable does not build or mutate the open scene.
- [ ] Open `N → AWFUL STUDIO` and run **Build Studio**.
- [ ] Generate Bottle / Jar / Box / Can / Phone / Tablet; confirm grounding, bounds and Auto Fit are sensible.
- [ ] Check Product Once / Loop / Ping-Pong and confirm the Preview Range is useful.
- [ ] Check Camera Once / Loop / Ping-Pong independently and with Product motion active.
- [ ] Switch representative Commercial / Flash / Natural / Hybrid lighting; confirm World + Studio no longer destructively overexposes the product.
- [ ] Toggle camera-visible BG and confirm it does not change product illumination.
- [ ] Exercise Download All HDRIs/status/error path and confirm successfully downloaded assets do not produce Blender magenta.
- [ ] Run **Setup Post Pipeline**, confirm Ready state, Light Groups/passes/compositor workflow, then repeat it once to verify rebuild behavior.
- [ ] Save the `.blend`, close Blender, reopen it and confirm both Studio and Post setup remain usable.
- [ ] For Rendered Viewport performance, use the normal workstation profile and deliberately set the Cycles scene Device to **GPU Compute**; compare Fast Preview and Quality Preview while navigating the camera.
- [ ] Run Rebuild and confirm the selected mockup/Auto Fit state remains usable.
- [ ] Run Remove Studio and confirm unmanaged user data remains.

If any smoke item fails, do not tag or publish 0.0.17. Record the exact candidate SHA/artifact, Blender version and reproduction steps and build a new canonical candidate after the fix.
