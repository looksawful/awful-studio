# AWFUL STUDIO 1.0.0

Status: first stable public release.

AWFUL STUDIO 1.0.0 promotes the structurally qualified 0.0.17 feature set into the first stable release. The release policy is deliberately pragmatic: functionality that is implemented and covered by the current packaged-runtime gates ships now; unfinished visual libraries, device assets and research work remain tracked for patch/minor releases instead of blocking 1.0.0 indefinitely.

## Included in 1.0.0

### Studio lifecycle and safety

- Blender Extension package for Blender 5.2 LTS.
- Explicit Build / Rebuild / Remove workflow.
- Import/register/enable/restart do not build or mutate the open scene.
- Ownership-scoped generated data and protection of unmanaged user data.
- Explicit historical 0.0.15 migration path.
- Factory Cube/Camera/Light cleanup only for an untouched first-build factory scene.

### Product workflow

- Procedural Bottle, Jar, Box, Can, Phone and Tablet starter mockups.
- Deterministic product grounding from actual world-space bounds.
- Auto Fit integration for product placement and camera framing.
- Offline starter materials.
- Product replacement preserves unmanaged mounted user content.

### Camera and motion

- Product and Camera animation remain independent.
- Once, Loop and Ping-Pong playback policies.
- Blender Preview Range follows generated motion without destructively changing the global render frame range.
- Product-bounds camera framing without the historical fixed-distance clamp.

### Studio architecture

- Metric cyclorama controls.
- White / Black / Chroma Green looks.
- Matte / Medium / Glossy finishes.
- Independent cyclorama, room, floor, ceiling, door and window visibility controls.

### Lighting and environment

- Commercial/product-lighting presets and photographic Flash family.
- Natural Light, Physical Sky and reviewed HDRI modes.
- Hybrid Studio + World lighting.
- Independent environment illumination and camera-visible background brightness.
- Explicit Fast Preview / Quality Preview viewport profiles without changing final render settings or silently changing the Cycles device.

### Optional HDRIs and cache

- Five reviewed Poly Haven HDRIs available through explicit opt-in download.
- Blender Online Access and AWFUL network consent remain separate permissions.
- Provenance-bound cache validation and cleanup.
- Missing optional HDRI data falls back safely without silently presenting a broken environment as valid.

### Post Pipeline

- Optional Setup Post Pipeline workflow.
- Cycles Light Groups, required passes and managed compositor setup.
- Live capability detection, explicit success/failure state and idempotent rebuild behavior.
- Save/reopen ownership safety.

### Release engineering

- Official Blender Extension CLI validation/build.
- Exact Blender 5.2.1 qualification runtime pinned in `runtime/blender.lock`.
- One canonical ZIP built on Ubuntu and verified byte-for-byte on Windows.
- Native static Blender Extension Repository generation/sync/install verification on both platforms.
- Fast/static and packaged Blender runtime contracts.
- No render invocation in ordinary structural CI.

## Binary-asset integrity change

The pre-release candidate exposed corrupted bundled ambientCG PaintedPlaster PNGs caused by Git text EOL normalization. Those invalid binaries are intentionally excluded from 1.0.0 rather than shipped knowingly broken.

1.0.0 therefore uses the existing procedural/offline material fallback for the affected floor/cyclorama surface. The ambientCG source remains recorded as provenance/reference material but is not bundled or authorized as an active download in this release. `.gitattributes` now marks common media formats as binary so future reviewed assets cannot be newline-normalized.

A verified reintroduction of the PaintedPlaster maps may ship in a patch release after source restoration and binary/runtime validation.

## Verified compatibility

- Blender 5.2 LTS.
- Exact qualification runtime: Blender 5.2.1 build `9e2066aef7ef`.
- Manifest range: Blender `>= 5.2.0` and `< 5.3.0`.
- CI qualification platforms: Ubuntu and Windows.

## Known limitations

These are explicitly non-blocking for 1.0.0 and remain tracked for later work:

- deterministic rendered visual-regression harness (#4);
- final visual/product passes for Scene Lab v3 (#48);
- production LOW/HIGH device mockups and their plugin delivery contract (#49–#54);
- physical studio-equipment asset library research/modeling (#55 and follow-up work);
- larger motion, HDRI, fixture and volumetric libraries;
- optional Flue live bridge evaluation (#1);
- optional Blender Agent Studio evaluation (#2).

The release does not claim that unfinished device blockouts or Scene Lab experiments are production assets. They are not silently promoted into the Extension package.

## Installation

Install the exact `awful_studio-1.0.0.zip` from the GitHub release through Blender **Edit → Preferences → Extensions → Install from Disk**. See `docs/INSTALL_UPDATE.md` for the full workflow and troubleshooting.

## Update policy

- `1.0.x`: correctness, packaging, compatibility and contained UX fixes that do not require a product-contract break.
- `1.x`: additive production features, asset libraries and workflow improvements.
- `2.0.0`: reserved for a deliberate incompatible product/runtime contract change.
