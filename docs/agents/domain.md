# Domain docs

Layout: single-context.

## Canonical locations

- Root domain glossary/context: `CONTEXT.md`
- Architecture decisions: `docs/adr/`

## Consumer rules

- Read `CONTEXT.md` before changing domain vocabulary or introducing a new long-lived concept.
- Record hard-to-reverse architecture decisions under `docs/adr/`.
- Do not duplicate implementation status here; GitHub Issues own implementation work and status.
- If `CONTEXT.md` or `docs/adr/` does not yet exist, create it only when the current work actually needs domain/ADR material.
