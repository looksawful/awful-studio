# Research and documentation sync

When research informs AWFUL STUDIO, explicitly distinguish:

- verified current project state;
- external reference or source;
- recommendation/hypothesis;
- installed and tested integration.

Do not present a candidate, benchmark idea, MCP, addon or upstream skill as installed/supported until the repository's adoption criteria and target Blender 5.2 runtime evidence are satisfied.

Use Notion for business/product/architecture decisions when those decisions genuinely change. Use GitHub issues for implementation work and evidence. Skills describe repeatable methods only; they are not a status database.

When documentation changes because implementation changed, update only after verifying the new behavior. Preserve uncertainty where evidence is incomplete.
